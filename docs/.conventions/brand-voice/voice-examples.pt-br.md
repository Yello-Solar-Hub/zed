# Exemplos de transformação de voz

Dez transformações “antes e depois” que demonstram a voz da marca Zed. Use-as como referência para o diagnóstico e a reconstrução.

## 1. Do entusiasmo aos detalhes

**Antes (Pontuação: 2/5 – Fundamentos técnicos)**

> O Zed oferece um desempenho extremamente rápido que vai revolucionar sua experiência de programação. Nossa tecnologia de ponta garante que você nunca mais precise esperar.

**Depois (Nota: 5/5)**

> O Zed foi desenvolvido em Rust com renderização acelerada por GPU. As teclas são registradas em menos de 8 ms. A rolagem mantém 120 fps mesmo em arquivos grandes.

**Notas sobre a transformação:**

- "incrivelmente rápido" → valores específicos de latência
- "revolucionar" → removido por completo
- "tecnologia de ponta" → pilha de tecnologia atual
- "Nunca mais espere" → afirmação mensurável

## Regras de preservação de fatos

Ao adaptar o texto, certos elementos devem permanecer inalterados:

### Marcação durante o diagnóstico

Marque as afirmações factuais com `[FACT]` durante a fase de diagnóstico:

```
Zed is written in [FACT: Rust] with [FACT: GPU-accelerated rendering].
It was built by [FACT: the team behind Atom and Tree-sitter].
```

### Nunca mude

| Categoria           | Exemplos                                   |
| ------------------ | ------------------------------------------ |
| Especificações técnicas    | "120 fps", "latência de 8 ms", "Rust"            |
| Nomes próprios       | "Tree-sitter", "Anthropic", "Claude"       |
| Números de versão    | "Zed 1.0", "v0.150"                        |
| Atalhos de teclado | "cmd+shift+c", "ctrl+\`"                   |
| URLs               | "zed.dev/releases"                         |
| Atribuição        | "desenvolvido pela equipe responsável pelo Atom"            |
| Datas              | "disponível hoje", "lançado em janeiro de 2024" |
| Citações             | Qualquer citação atribuída                   |

### Etapa de verificação

Após a reconstrução, comparação com os marcadores originais `[FACT]`:

1. Listar todos os fatos do original
2. Confirme se cada um deles consta na versão final
3. Se algum fato foi removido, justifique o motivo (por exemplo, por não ser relevante para o novo escopo)
4. Se um fato foi alterado, sinalize como erro

### Verificação de exemplo

**Original com marcações:**

> O Zed é [FATO: escrito em Rust] e conta com [FATO: renderização acelerada por GPU a 120 fps]. Desenvolvido por [FATO: a equipe por trás do Atom e do Tree-sitter].

**Reconstrução:**

> O Zed renderiza cada quadro na GPU a 120 fps. O código-fonte do Rust prioriza a segurança da memória sem pausas para coleta de lixo. Os mesmos engenheiros que criaram o Atom e o Tree-sitter lideram o desenvolvimento.

**Verificação:**

- ✅ “Ferrugem” preservada
- ✅ “Acelerado por GPU” mantido
- ✅ “120 fps” mantidos
- ✅ “equipe por trás do Atom e do Tree-sitter” mantida
- **Passar**

## Resumo dos Padrões de Transformação

| Problema              | Solução                     |
| -------------------- | ---------------------------- |
| Palavras da moda           | Substituir por medidas    |
| Cadeias de travessões longos       | Dividir em frases         |
| "Não é X, é Y" | Descreva de forma positiva o que é  |
| Entusiasmo           | Excluir; acrescentar conteúdo        |
| Benefícios vagos       | Nomeie características específicas       |
| Notícia principal escondida          | Comece com as notícias           |
| Perguntas retóricas | Faça afirmações declarativas  |
| Reivindicações abstratas      | Adicionar mecanismo ou medida |
